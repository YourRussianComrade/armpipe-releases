# ArmPipe-Diag — проверка связи ПК с ПЛК и камерами

`ArmPipe-Diag.exe` — утилита для ПК машины санации и инспекции труб. Она проверяет связь компьютера с **ПЛК** (Modbus TCP) и с **камерами** (RTSP/ONVIF). Если что-то не так, утилита подсказывает, где искать причину.

Установка не нужна: скопируйте exe на ПК с ArmPipe и запустите двойным щелчком.

## Откуда берутся адреса

Утилита сама читает настройки ArmPipe из `%LOCALAPPDATA%\ArmPipe\config.json`. Используются те же параметры, что в программе:

| Что | Ключи config.json | По умолчанию |
|---|---|---|
| ПЛК | `plc.ip`, `plc.port`, `plc.unit_id`, `plc.use_unit_id`, `plc.start_address`, `plc.count` | порт 502, адреса 612…616 (V100…V104), Unit ID 1 |
| Датчик затопления | `flood.register_v`, `flood.invert` | V102 (адрес 614) |
| Камера 1 (PTZ) | `camera.ip`, `user`, `password`, `rtsp_port`, `main_path`, `sub_path`, `onvif_port` | RTSP 554, `stream1` / `stream2`, ONVIF 2020 |
| Доп. камеры | `extra_cameras[]`: `ip`, `user`, `password`, `rtsp_port`, `path`, `sub_path` | RTSP 554, `stream1` |

Если файла настроек нет, утилита попросит ввести IP ПЛК и камеры вручную.

## Что проверяется

**Сетевые карты ПК.** Утилита показывает их адреса и проверяет, есть ли карта в той же подсети, что ПЛК или камера. Это самая частая причина отсутствия связи.

**ПЛК:**
1. Ping: 4 пакета, потери и время отклика.
2. TCP-порт Modbus (502): открыт, закрыт или не отвечает.
3. Пять чтений holding-регистров. Значения расшифровываются так же, как в ArmPipe: дистанция, температура, затопление, код аварии, режим.

**Каждая камера:**
1. Ping.
2. RTSP-порт.
3. Запрос `DESCRIBE` к основному и дополнительному потоку с логином и паролем из настроек. Так видно, что именно не так: нет связи, неверный пароль (401) или неверный путь потока (404).
4. ONVIF (`GetSystemDateAndTime`): работает ли управление PTZ.

В конце выводится **итог** по каждому устройству: `СВЯЗЬ ЕСТЬ` / `ЕСТЬ СБОИ` / `НЕТ СВЯЗИ`. Отчёт сохраняется в текстовый файл в папку `reports` рядом с exe. Если туда нельзя записать — в `%LOCALAPPDATA%\ArmPipe\diag`.

## Меню после проверки

- **Enter** — проверить ещё раз.
- **M** — мониторинг ПЛК в реальном времени: опрос каждые 0,5 с со строкой значений. Удобно, чтобы пошевелить кабель или разъём и увидеть, пропадает ли связь. Выход — Enter, в конце выводится число ошибок и обрывов.
- **Q** — выход.

## Параметры командной строки

```
ArmPipe-Diag.exe -plc 192.168.1.10           IP ПЛК вместо значения из настроек
ArmPipe-Diag.exe -plc 192.168.1.10 -port 502
ArmPipe-Diag.exe -cam 192.168.1.20           IP основной камеры
ArmPipe-Diag.exe -config D:\config.json      другой файл настроек
ArmPipe-Diag.exe -monitor                    сразу мониторинг ПЛК
ArmPipe-Diag.exe -once                       одна проверка без меню; код выхода 1, если есть «НЕТ СВЯЗИ»
```

## Типичные результаты

| Результат | Что делать |
|---|---|
| Нет сетевой карты в подсети ПЛК/камеры | Задать карте ПК IP из той же подсети (например, ПЛК 192.168.1.10 → ПК 192.168.1.100, маска 255.255.255.0) |
| Ping нет, порт не отвечает | Питание ПЛК/камеры, кабель, индикаторы LINK, IP-адреса |
| Ping есть, порт «отклонено» | В ПЛК не включён Modbus TCP сервер, неверный порт или исчерпан лимит подключений (закрыть ArmPipe и повторить) |
| Порт открыт, Modbus «тайм-аут» | Неверный Unit ID или на порту не Modbus TCP |
| Исключение Modbus 2 | Неверные `start_address`/`count` или программа ПЛК |
| Камера 401 | Неверный логин или пароль камеры в ArmPipe |
| Камера 404 | Неверный путь потока (`stream1`/`stream2`) |
| ONVIF не отвечает | Не будет работать поворот и зум; проверить порт ONVIF (2020) и включён ли ONVIF в камере |
